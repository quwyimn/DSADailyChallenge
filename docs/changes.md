# CHANGES.md — Change log (AI must append here)

> **Mandatory:** whenever you (the AI) change anything non-trivial — add/remove a dependency,
> deviate from a rule, alter the data model, change an API contract, take a shortcut, or make
> any decision a human didn't explicitly ask for — you MUST append an entry here in the SAME
> change, before finishing. No silent changes. If you skip this, the change is incomplete.

## When to log (if in doubt, log)

- Added, removed, or upgraded a dependency.
- Changed the Prisma schema / data model.
- Changed an API endpoint's path, request, or response shape.
- Deviated from anything in `RULES.md` (must also include WHY + that you flagged it).
- Took a deliberate shortcut / introduced technical debt (also add to `MEMORY.md` debt log).
- Renamed/moved files or changed folder structure vs `MAP.md`.
- Any decision the developer did not explicitly request.

## What NOT to log here

- Routine implementation that follows the plan (that's just normal work).
- Pure bug fixes with no decision attached (those go in `MEMORY.md` bug journal).

## Entry format (copy this)

```
### [YYYY-MM-DD] Short title
- What: <what changed, concretely>
- Why: <reason>
- Scope: <files / modules affected>
- Rule impact: <none | deviates from RULES #N — flagged to developer>
- Follow-up: <none | what still needs doing / debt added to MEMORY.md>
```

### [2026-06-15] New challenge strategy — binary_search
- What: Added `backend/src/challenges/strategies/binary-search.strategy.ts`, following the existing `bubble_sort`/`linked_list` `ChallengeStrategy` pattern. Config: `{ array: number[] (sorted ascending, unique, 5–15 elements, 1–99), target: number, targetExists: boolean, points?: number }`. `computeBinarySearchSteps()` runs the standard iterative binary search (`mid = floor((low+high)/2)`), returning one step per comparison — `{ low, high, mid, value, found, eliminated: 'left'|'right'|'none' }` — stopping on `found` or `low > high`. `generateConfig()` produces 5–15 unique ints in 1–99 (via a `Set`, sorted ascending), then picks `target` from the array 70% of the time (`targetExists: true`) or a number not in the array 30% of the time (`targetExists: false`); `points: 10`. `validateConfig()` checks the array is non-empty, all-finite-number, **strictly ascending** (sorted + no duplicates in one pass), plus `target: number` and `targetExists: boolean`. `grade(config, actions)` — `actions = [{ mid: number }]` — compares the user's `mid` sequence to `computeAnswer`'s `mid` sequence element-by-element (length + values); `isCorrect` requires an exact match, `points = config.points ?? 10` if correct else `0`. `validate()` does a full step-by-step comparison (`mid`, `found`, `eliminated`, `low`, `high`) for completeness, mirroring the other strategies' `validate`/`grade` split. Registered via `registerStrategy('binary_search', binarySearchStrategy)` in `challenge-registry.service.ts` (the only registration point — confirmed via grep, no other file lists challenge type strings).
- Worked-example discrepancy (flagged, not silently resolved): the task spec's example — `array=[1,3,5,7,9,11,13], target=7 → mid sequence [3,5,4], found at index 3` — does not hold under the spec's own algorithm ("stop when found or low > high"). With `mid = floor((low+high)/2)`, the first step for this array/target is already `low=0, high=6, mid=3, value=arr[3]=7` → **found immediately**, so the correct mid sequence is `[3]`, not `[3,5,4]`. The `[3,5,4]` sequence is what this exact array produces for an **absent** target between 9 and 11 (e.g. `target=10`, not found, eliminated left/right/left). Implemented `computeBinarySearchSteps` per the stated algorithm (verified by running it standalone — see below); the inline comment in the strategy file documents both the `target=7` (`[3]`, found) and `target=10` (`[3,5,4]`, not found) cases for future reference. No code written to special-case the `[3,5,4]`-for-`target=7` example, since that would require a non-standard search order not described anywhere else in the spec.
- Verified: `npx tsc --noEmit` clean; `npx jest` 7/7 passing (unchanged — no existing tests reference this strategy). Ran `computeBinarySearchSteps([1,3,5,7,9,11,13], 7)` → `[{low:0,high:6,mid:3,value:7,found:true,eliminated:'none'}]`; `..., 10)` → `[{mid:3,...,eliminated:'left'},{mid:5,...,eliminated:'right'},{mid:4,...,eliminated:'left'}]` (the `[3,5,4]` sequence); `..., 11)` → `[{mid:3,eliminated:'left'},{mid:5,found:true}]` — all match manual hand-traces.
